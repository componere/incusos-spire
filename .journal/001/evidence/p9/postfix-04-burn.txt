### postfix-04 — the burned-nonce contract, proven deliberately
### 2026-08-17T16:27:15Z

WHY: EVIDENCE.md recorded outcome=burned only as a MEASURED accident (guest B, finding F3),
before the fix that names the condition to the caller. The fixed broker returns a specific
error code for it. This forces the condition on purpose, on guest A, and then proves the
nonce really was spent.

LEVER CHOSEN: temporarily delete the exchange registration entry. The broker's Broker API
call then reaches a healthy host agent, the host agent re-derives incus:uuid:a955ca30-...,
the server finds NO entry matching it, and returns an empty SVID list. This is the cleanest
lever because it leaves the broker binary, its configuration, its TLS identity and the
Broker API socket completely untouched -- only one server-side record moves, and it is
restored verbatim afterwards. Pointing the broker at a bogus socket path would also work
but would require editing /state/broker.env and restarting the service.

THE CONTRAST, WHICH IS THE WHOLE POINT
======================================================================
redemption that burned the nonce   HTTP 503  {"error":"nonce_consumed_without_svid"}
replay of that same nonce          HTTP 409  {"error":"conflict"}

Two different codes for two different facts. The 503 says 'your nonce is spent and you got
nothing for it -- go get a fresh one', which is actionable. The 409 is the ordinary
single-use conflict and is unchanged from the pre-fix broker: the burn code does NOT leak
into the replay path, so a caller cannot use it to probe whether a nonce was burned or
merely reused.

The log line carries everything an operator needs to reconcile it:
  outcome=burned  nonce_id=dbb0096ee125b97b40168e7981b3b3ff
  instance_uuid=a955ca30-a0dc-4087-a369-37d53d389c5a
  failure_class=broker_no_svid  http_status=503  code=nonce_consumed_without_svid
  level=ERROR

CHANGE VISIBLE AGAINST THE OLD BINARY: the same condition on the pre-fix broker logged
code="unavailable" (see EVIDENCE.md N3 / negative-02-guest-b.txt, and the 15:43:45 line
still in the journal). It now logs code="nonce_consumed_without_svid", matching the body.
The HTTP status class is preserved: 503 for this dependency failure, not a new status.
