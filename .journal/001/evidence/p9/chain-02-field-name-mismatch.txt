### diagnosis
cmd/incus-spiffe-broker returns the three PEM blobs as flat top-level fields named
exchange_cert_chain_pem / exchange_key_pem / exchange_bundle_pem. spike/p9/README.md's
"Redeem response shape it accepts" table lists neither those spellings nor the exchange_
prefix at any of its four nesting points, so the harness's automatic lookup missed all
three. The harness behaved correctly under Appendix D: it named the fields it looked for,
withheld the body because it may contain a key, shredded the tmpfs, and exited 4.

The nonce was consumed by this run (HTTP 200 was returned), so the retry below needs a
fresh nonce. Fixed by passing the explicit filters the harness documents for exactly this
case: CHAIN_JQ / KEY_JQ / BUNDLE_JQ.
