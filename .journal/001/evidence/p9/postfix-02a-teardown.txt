attestation, which would make the clean re-run impossible. 'evict' deletes the attested
node record, so the server no longer knows this node and the next attestation is a FIRST
attestation, not a re-attestation. The node identity that comes back is byte-identical
because x509pop derives it from the exchange SVID's SPIFFE ID, which the broker derives
from the instance UUID -- a955ca30-... is a property of the Incus instance, not of any
credential. So a stable ID here is evidence the derivation is deterministic, not evidence
that the old node survived.
